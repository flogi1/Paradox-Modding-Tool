v0.9.1 (02.10.2026)
New
- Fixed: the release tool aborted at the "Tests" step because the real-save load test compared a 236 MB save against a 3 s limit while all test projects ran at once (6.5 s under load, 1 s alone). The limit is now a 15 s guard against gross regressions.
- Warnings after replacing (OR/NOR/AND blocks with one entry or none): saving a file (Save, Save all, Ctrl+S) now updates them automatically, as the refresh button does. Places that were fixed drop out of the list, the rest get their current line. It only runs when the saved file has warnings. With "show warnings in their own window", an open warning window is replaced when the list changed and closes when nothing is left; a window you closed stays closed.
- Result lists (Find & Replace window and results bar): you can now select several matches (Ctrl+click, Shift+click, Ctrl+A); Ctrl+C or "Treffer kopieren" copies all selected matches, one block each, separated by a blank line, and the new context menu entry "Alle Treffer kopieren" copies the whole list. A read-only text box under the list shows the code of the selected matches, so parts of a match can be selected and copied with Ctrl+C; it appears only while something is selected. Double-click still jumps to the match.
- Mod compatibility check, sense check: an entry whose copy only gives existing subkeys a new simple value (e.g. cost = 1 becomes cost = 2), with or without new subkeys, now gets the hint "Nur Werte geändert" (INJECT: is enough) instead of "Ersetzung nötig" (REPLACE:), because INJECT: overwrites an existing subkey in place (measured in Europa Universalis V). REPLACE: stays the advice for removed or reordered subkeys, changed sub-blocks and repeated keys. The same rule now also decides "Nur Ergänzung": a subkey inserted before existing ones (e.g. an else_if before else) or one that repeats an existing key is no longer called a pure addition, because INJECT: appends at the end and overwrites a repeated key.
- Compatch creator: the patch form "INJECT:" is now also offered when a subkey only gets a new simple value (e.g. cost = 1 becomes cost = 2), not just for pure additions. The patch then holds only the changed and the new subkeys, and INJECT: overwrites the existing subkey in place (measured in Europa Universalis V). Removed or reordered subkeys, changed sub-blocks and a new entry that repeats an existing key still get REPLACE: or a whole file. Fixed along the way: an addition that repeated a key the entry already had was offered as INJECT:, which would have overwritten that subkey instead of appending it.
- Desync analysis (OOS dump window), Europa Universalis V: new tab "MP-Prüfung" checks your own mods (or, with "ganzes Playset", the whole playset) for script that can make a multiplayer game go out of sync, for example has_local_dlc in synced script or console commands in .gui files that are not interface-only. Each finding shows its severity, file, line, context and an explanation; double click jumps to the file. With an OOS selected it checks the mods from the dump (unless "Vorabprüfung statt Dump-Mods" is ticked) and ranks their files as suspects by log leads, rule findings and terms from the state comparison. Log leads are matched against the mods in the dump (in the dump's load order), and a file with a log lead always ranks above files that only have rule findings. Findings can be marked harmless or confirmed as risky (context menu); the verdict is kept per game. The check only starts on "Prüfen" and nothing is written to mod files.
- Menu bar: "Komp-Patch Tool" now sits right next to "Mod-Kompatibilität prüfen".
- Fixed: the mod compatibility check reported .metadata/metadata.json (and other files directly in the mod folder, such as descriptor.mod or thumbnail.png) as a file conflict between two mods, and its sense check could call them redundant. These files describe the mod and are never loaded as game content, so they are now skipped, as the Compatch creator already did.
- Fixed: Compatch creator and mod compatibility check treated INJECT: as if it only appended subkeys, so a subkey that vanilla or another mod already sets appeared twice in the computed game state (e.g. gold = 10 and gold = 999) and such cases were marked uncertain. Measured in Europa Universalis V: INJECT: overwrites an existing subkey in place (INJECT:build_gravel_road = { gold = 999 } costs 999, not 10). PMT now replaces the subkey and adds only new ones; when two mods INJECT the same subkey with different values, the conflict names the mod whose value applies and is no longer uncertain. Only an overwritten sub-block (e.g. modifier = { ... }) stays uncertain, because it is not measured whether the game replaces or merges it.
- Error log (Europa Universalis V): more messages are recognised and explained. New kinds for a country without a valid government type (government_type link), duplicated production method names (named after the building, so "find definition" jumps to it), modifier types without localization (MODIFIER_TYPE_NAME_/DESC_ placeholders) or icon, unlocalized text in .gui files, unknown input actions of widgets, incorrect DLC checksums, countries with missing setup entries (government, heir selection, capital, laws, society values, parliament type), unrecognized localization keys in events, modifiers used in a scope that does not accept them, mods disabled after a crash at the previous start (sentinel file), and, seen with the 1.4 open beta, script checks that failed validation (PostValidate, e.g. has_dlc for a DLC that does not exist), links to entries missing in the database, effects without localization, invalid DLC names in setup data, generic actions missing from or unknown to the AI lists, unit illustration masks without illustration, missing portrait templates, unused static modifiers, and the harmless vanilla messages about GUI widgets without data context and DLC thumbnails that cannot be opened. "Badly read script value" with a value, "Could not find promote for", "Failed to convert statement for argument" and "Could not find audio event" now fall under the existing script value, localization and sound kinds, as do texts the game generates for missing localization keys and missing STATIC_MODIFIER_NAME_ keys.
- Mod compatibility check warns about replace_path entries that cannot work: in Europa Universalis V an entry starting with in_game/, main_menu/ or loading_screen/ has no effect, because replace_path names folders without that root (hint "replace_path wirkt nicht", with the form to write instead); in Europa Universalis IV an entry naming a subfolder of interface/ that holds .gui files of a mod in the check makes the game crash at startup (conflict "replace_path: Absturz"). The warnings cover every mod of the run, not only Mod 1. The game profile decides both (replacePathRoots, new replacePathGuiCrashRoots).
- Desync analysis (OOS dump window): new tab "Bericht" prepares a desync report in English for two recipients. For the Paradox bug form it lists every form field one by one with its own copy button (the fields are defined per game in the game profile, EU V for now) and offers the OOS dumps as attachments, folder dumps can be saved as a zip file. For mod authors it creates a report as Markdown text (copy it or save it as a .txt file) with the leads, state differences and advice. A local bug entry can be created with links to your own mod files. PMT never fills in or sends anything to a browser form by itself.
- Patch recipes, Wächter tab: new button "Ordner ignorieren" ignores every file in the folder of the selected file, subfolders included (e.g. common/customizable_localization), in one step with an optional note; "Nicht mehr ignorieren" on one of those files removes the folder rule. Recipes saved earlier load unchanged.
- Patch recipes, Rules tab: new button "Fehlendes aus der Vorlage ergänzen" (only for recipes created from a preset). It lists what the recipe lacks compared with its preset (rules, columns, edits in existing rules, Wächter search patterns) and, after confirmation, adds only that; existing rules, hand changes and switched-off rules stay unchanged, an edit you deleted comes back. This brings recipes created before the preset extensions up to date.
- Fixed: Find & Replace in "Aktuelles Dokument" mode searched and replaced only in the left workspace when split view was on, because the search window has the keyboard focus and PMT then fell back to the left workspace. It now uses the workspace that was focused last (and still the one with the focus, if any), so searching, replacing and jumping to a hit work in the right workspace too.
- Patch recipes: every rule in the Rules list has a checkbox at the left to switch it on or off without deleting it. New rule kind "Block bearbeiten": applies edits (insert into, insert after, remove ...) directly to existing blocks in your mod's files, with no copy and no own target file; a block that exists only in vanilla gets the mod copy of its vanilla file first (option "Kopie aus Vanilla anlegen, wenn sie fehlt"), "Folgestufen mitnehmen" includes the next_building chain, and only missing lines are inserted, so a second run changes nothing.
- Patch recipes, second preset "CK III: Ressourcen in Special Buildings" ("Neues Rezept" > "Aus Vorlage"): it inserts the resource effects of Flogi's Buildings and Technology Mod into on_start and on_cancelled of every level, in place in the existing building files. "Specials aus Vanilla einlesen" lists all specials, whether or not they have a place in the history (meant for specials that stay special, e.g. generic mines or Pleasure Dome; specials the first preset converts get the effects there).
- Patch recipes, preset "CK III: special buildings into normal buildings": the preset now also creates four rules trigger_level_01 to 04 that rewrite building_requirement_castle_city_church = { LEVEL = 01 } to 04 into building_requirement_main_building = { LEVEL = 2 }, 4, 6 and 8 in the generated buildings, and its block copy inserts the resource effects (flogis_techmod_subtract_wood/stone/metal/luxury_250 in on_start, the matching add_ effects in on_cancelled) into every converted building and every upgrade level. Existing on_start or on_cancelled blocks are extended, a missing one is created; for adopted blocks only the missing lines are added. A Replace rule with kind Text now also finds matches across several lines, so the multi-line form of a block is replaced like the one-line form. Both parts belong to Flogi's Buildings and Technology Mod: switch the four rules off and switch off the two "Einfügen in" edits (every edit of a block copy now has an "Aktiv" checkbox) if you do not need them. Recipes created earlier keep their rules; add the edits in the Rules tab under "Bearbeitungen".
- Fixed: "Ordner öffnen (Explorer)" in the directory overview opened only the Documents folder when the path mixed / and \ (e.g. ...\Crusader Kings III/mod\<Mod name>), because Windows Explorer ignores such paths. Folder roots now get clean backslash paths (the tooltip shows them too), and every open-folder action (editor, compare pane, My Mods, translation folder) cleans the path before calling Explorer. Documents restored from an older session and the start folder of the folder and file dialogs get the clean path too.
- Script suggestions no longer list the game's custom localizations (e.g. GetName); the new setting "Custom Localizations in den Vorschlägen anzeigen" (workspace settings, default off) brings them back. The hover tooltip still knows them.
- Find & Replace results (Find window and results bar): the found code is no longer a text field, so you cannot click into a match and get a cursor; a double-click jumps to the place. To copy the found code use Ctrl+C or right-click > "Treffer kopieren".
- Find & Replace and Replace lists: after replacing, PMT warns when an OR, NOR or AND block is left with only one entry or none (only blocks the replacement just made; blocks that were already like that stay quiet). The warnings appear in the Notes & bookmarks panel (new section "⚠ Nach dem Ersetzen" with every place of the last replacement; a double-click opens the place, ⟳ refreshes the list against the current text so fixed or undone places drop out and moved ones get their new line, ✕ clears the list); the new setting "Warnungen nach dem Ersetzen in eigenem Fenster zeigen" (workspace settings) shows a list window instead, which is also used when the panel is switched off. Nothing is deleted.
- Compare und Update Tool, Replace lists: rules have a kind. "Wort" is the known whole-word rule; "Text" takes any search text (also with { } = and several words), without word boundaries, and whitespace in it matches any whitespace including line breaks, so one rule finds the one-line and the multi-line form of a block; "Platzhalter" adds * for one word or value and $1, $2 in "Ersetzen durch" to reuse it (e.g. "special_building = *" to "#special_building = $1" hits every building). New option "Klammer schützen" for commenting out: when code such as the closing brace follows on the same line, the commented text goes on its own line and the rest stays active (buildings = { a b } with b gives a, #b, } on three lines). Comments are still left alone and a second run changes nothing; invalid rules are counted in the status line, and pasted rows get the fitting kind. Old lists keep working unchanged.
- Modifier values as in game, extended: hovering a script value or constant used as a modifier value (e.g. county_fertility_growth_mult = small_county_fertility_growth_gain, or = @constant) shows the value the game displays, read from common/script_values and common/scripted_variables of the game and the active mod (constants, references and inline formulas like @[ base + 0.05 ]; formulas with add/multiply/if blocks show nothing). The tooltip can also show the translated modifier name after the value (from the game's localization in your interface language, English as fallback; CK III, EU V and EU IV); the new setting "Modifier-Namen im Tooltip anzeigen" switches the name off. The new button "Modifier-Werte neu laden" (toolbar, can be hidden under Settings > Toolbar, and in the workspace settings) rereads the values and names, e.g. after you changed script_values files.
- Find & Replace: Ctrl+F with selected code puts the selection (also several lines) into the search field; Enter in the search or folder field starts the search, Shift+Enter starts a new line in the search field; Tab (and Shift+Tab) switches between "Aktuelles Dokument" and "Ordner oder Datei" outside the text fields (in the search and replace fields Tab stays a tab character); all keys are listed in the hotkey list; searching or replacing in a folder shows the general progress window with a progress bar and Cancel, and nothing is changed when you cancel. The window remembers the last searched folder or file (per game, also after restarting PMT).
- Desync-Analyse (new window in the main menu for Europa Universalis V): open OOS dumps from the game's oos folder or add dumps as zip or folder from other players (also one folder or zip holding both machines); the dumps of host and client are paired by OOS id; an overview lists the game versions, DLCs and enabled mods (with Workshop or local source) of both machines with warnings when they differ; the logs of both machines before the OOS are merged on game time with leads for script errors and invalid commands, and entries seen on only one machine are listed; state comparison of both OOS saves (takes a few seconds per pair) ranks findings into cause candidates, probable consequences and noise, with readable names; slot reuse in state changes is shown as such; results are cached under PMT's own data folder, and nothing is extracted or written into the game folder.
- Patch recipes (new window in the main menu): repeatable rule patches for a mod, as a table plus rules (line rules, block copies from vanilla, templates, list entries). The preview shows every file change before anything is written; lines can be taken back with U, conflicts with your hand edits are resolved per block, and Apply writes everything as one undo step with a mod snapshot. After a vanilla update merge PMT offers to apply the recipes again. Recipes are stored outside the mod, in PMT's storage location next to the snapshots ("<mod name> Patch Recipes"), so they are never uploaded.
- Patch recipes: the "Anleitung" button (or F1) opens a guide with a table of contents and a search field; it explains table, placeholders, the four rule kinds, preview, generated regions with hand edits and the steps after a vanilla update, with Angkor Wat as the running example.
- Patch recipes, new "Wächter" tab: lists every vanilla and mod file that uses the recipe's search patterns or row keys, with the status not covered (checked against what applying the recipe would leave), outdated (the Update tool would offer the file), own file, covered or ignored; actions add the file to a line rule with "create copy" (a rule whose file pattern has * and does not copy yet gets an identical rule for this file only, so only this file is copied), create a new (switched off) line rule, open the file at the line, open it in the Update tab, or ignore it with a note. File patterns in rules and derived columns accept several globs separated by ";".
- Patch recipes, preset "CK III: special buildings into normal buildings" ("Neues Rezept" > "Aus Vorlage"): five rules that comment the slot lines in history (all four forms, all places), replace the special-building iterators, remove the original definitions from mod copies of vanilla files, copy the buildings from all seven vanilla building files with an OR of all their baronies, and add them to the holdings; "Specials aus Vanilla einlesen" lists the vanilla specials with baronies (or "kein Ort") and whether the mod still defines them as special; "Bestehende Blöcke übernehmen" moves buildings the mod already defines into the generated region, converted, and keeps their hand edits. Engine: repeat sections {*column}...{/column}, derived columns with several searches (;) and "all hits", and a line-rule option for vanilla paths only.
- Patch recipes: new option "Zeilen ganz oder gar nicht" (rules tab): if one rule skips a row, every rule leaves it out, so no row ends half converted. The special buildings preset turns it on together with "Bestehende Blöcke übernehmen"; before, a building skipped as "bereits definiert" still got its slots commented and was listed in the holdings, which made the unchanged special buildable everywhere.
- Patch recipes: a recipe created from the special buildings preset opens "Specials aus Vanilla einlesen" right away, the dialog starts with "Nur in Mod noch Special" checked, and the preview says so when the table has no rows instead of showing nothing to do.

- Patch recipes, special buildings preset: specials without a place in history (generic mines, Pleasure Dome, Forbidden City and others whose slot an event, decision or great project grants and builds right away) now stay special. Fixed
- Patch recipes, small fixes:
  - "Vorschau berechnen", "Anwenden" and "Bestehende Blöcke übernehmen" can no longer close PMT on an unexpected error; the message shows in the status line.
  - An unreadable memory file is reported in the preview and kept as "<id>.memory.json.broken" when applying, instead of being emptied silently.
  - Applying refuses a preview in which an adopted block was taken back with U while its removal from the source file was not, so the block cannot get lost.
  - "Block entfernen" removes every definition of a key defined twice in one run.
  - Derived list columns (several places, several baronies) follow file order instead of the order of the search forms.
  - Typos in section names ({?x}, {!x}, {*x}, {/x}) are reported like unknown placeholders.
  - A line starting with "# PMT-Unit" or "# PMT-Patch" in a template or block text skips the file with a warning instead of splitting the unit.
  - No trailing space when the target block's closing brace shares its line with other content.
  - A leading "/" in a target path no longer makes the same file appear twice.
  - Import dialogs take only checked rows that are visible under the current filter; a missing game folder has its own message instead of "Kein Mod gewählt".
  - Watcher:
    - Files with conflicts no longer show as covered, since applying skips them.
    - An existing but empty game folder is reported.
    - Vanilla folders hidden by the mod's replace_path are not scanned.
    - After applying, or after a vanilla update merge of the same mod, the watcher says the scan is out of date.
    - Renaming a rule no longer asks for a rescan.
    - Adding a file to a switched-off rule says that the rule is off.
    - Switching the recipe during a scan scans the new recipe afterwards.
- Compare und Update Tool: U no longer takes lines while the comparison is paused (one side cannot be read as script, e.g. a localization file); before, it could take lines at the positions of the previously shown file.
- Compatch merge, view A: U did nothing after marking lines in the column preview while the search box still had the keyboard focus (the U went into the search). Marking lines now moves the focus to the preview.
- "Merge nach Update": a mod file that no longer has the content PMT wrote (for example copied back by hand) loses its saved decisions when the run is opened again; before, its places showed as done although the result was no longer in the file. Works for files written from this version on.
- Compatch merge: taking marked lines that leave the result unchanged (for example only commented-out lines) now says so instead of "Taken".
- Compatch merge, "Merge nach Update" and the Compare und Update Tool read the operators ?= and != (Crusader Kings III, Europa Universalis V); before, "x ?= { ... }" was split into "x" and "? = { ... }", and a rewritten block came out as broken script.
- "Merge nach Update" wrote broken .gui files (Crusader Kings III, e.g. hud.gui): a changed top-level window or widget was moved into the types block. - Compatch merge and "Merge nach Update": a block text made from marked lines keeps the formatting of the file it was taken from. - Compatch merge: taking marked lines of a block with U (compare window, view A) decided every place of the block at once, and a later single decision in that block dropped the taken lines again; now each changed place gets its own decision (A, B, vanilla or own text) and the other places stay open.
