v0.11.0 (16.10.2026)
New
- Patch recipes with an AI: "Mit KI erstellen" in the patch recipes window hands building a recipe to an AI of your choice. You describe the feature and the recurring task in your own words and add code examples or paths; PMT assembles the task (a guide, the files you choose from mod and game, your description, optionally the open recipe) as text to copy, as a file or as a folder, and takes the AI's answer back by pasting it or importing a folder. The answer is checked first (unknown fields, missing columns or lists, ids, paths), the AI's plain-language explanation is shown next to the preview of the file changes, and you decide there instead of reading rules. An open recipe can be handed over to extend or repair it; a recipe from another game or preset is adjusted to the current game on import. The guide also ships in the program folder (ai-guide/), and the new pmt-patch.exe lets an AI with file access check a recipe (check) and dry-run it against the real mod and game (plan, with --diff) without writing anything.
- Patch recipes now keep a description of what the recipe does and read recipes from AI answers tolerantly (code fences, comments, trailing commas, enum values in any case, null lists).
- Error log, "Mod ins Playset aufnehmen" now works for the launcher games too (Crusader Kings III, Victoria 3, Europa Universalis IV): PMT puts the mod before your first own mod in the playset, backs up the launcher database first and writes nothing while the game or the Paradox Launcher is running.
- Playsets: the new window "Playsets verwalten" (tile bar, classic menu) creates, copies, renames and deletes the playsets of the game and edits their mods (add with keyword search, remove, reorder, switch on and off) and DLCs, for Crusader Kings III, Victoria 3, Europa Universalis IV (Paradox Launcher database) and Europa Universalis V (playsets.json). Existing playsets can be edited too. "Start with this playset" writes the files the game reads and starts the game directly; for the launcher games PMT also writes dlc_load.json / content_load.json. Before every change PMT backs up the database or playsets.json together with the load file (the last 10 sets stay, "Sicherungen" restores one) and writes nothing while the game, or for launcher games the Paradox Launcher, is running. In the mod list, right-click a test mod: "Mit aktuellem Playset plus dieser Mod starten" or "Neues Playset aus aktuellem Playset plus dieser Mod". The toolbar playset list now also switches launcher-game playsets when the profile names a load file.
Changed
- Patch recipes: paths in recipes (files, targets, lookup files) must stay inside the mod and game folders: a rule with an unsafe path is skipped with a reason, a row whose key or own-column value would lead outside is skipped alone, and the plan writer refuses files outside the mod. A target must be the path of a single file, and a column name with a trailing line break is invalid.
- The IV2 package: the generic actions refresh the IV2 alerts right after player actions, and every historic idea uses its own scripted trigger.
- Russian texts address the user informally ("ты") throughout.
- Starting a playset from the toolbar now refuses while the Paradox Launcher is open for launcher games (it would overwrite the playset files), and starting the same unchanged playset again no longer adds a new backup set, so older backups stay.
Fixed
- Unexpected errors no longer end PMT: they are written to error.log in %LocalAppData%\ParadoxModTool, shown once in a message and PMT keeps running (an error before the main window appears still ends it, so the game lock is not held).
- The Desync analysis entry no longer shows up in the menu bar of the new layout.
- The AI window keeps the game files you ticked when you change the game folder.

v0.10.0 (12.10.2026)
New
- Victoria 3 is now a supported game (game menu, between Crusader Kings III and Europa Universalis V). PMT finds the Steam install and the mod folder, reads the documentation logs from the game's "docs" folder (including the new block format of modifiers.log, 7090 modifiers) and the data types for the GUI editor, shows modifier names and values on hover (also with game concepts written as [concept_x]), and knows the override rules of the official wiki for mod compatibility and the Compatch: INJECT and REPLACE work only in the folders the wiki lists, four folders (script_values, scripted_effects, scripted_rules, scripted_triggers) know only REPLACE, and INJECT appends to an entry instead of overwriting its values, so PMT suggests INJECT only for pure additions there and REPLACE for changed values. GUI types and events: the first one loaded wins. Not yet for Victoria 3: the save explorer.
- Victoria 3 error log: a catalog of 36 message types, learned from a test run with deliberate errors, explains each message of error.log in German and English with fixes (jump to the place, find the definition, suppress …). It covers, among others, INJECT/REPLACE on entries that do not exist, INJECT of a trigger block the entry already has, unknown modifier types, events without a valid namespace, duplicate event ids, localization files without BOM or with a missing colon, and the vanilla messages "Failed to read key reference" without a file (marked as harmless). Scope traces read the scopes Victoria 3 writes to debug.log.
- Victoria 3 GUI building blocks: the 16 blocks of the GUI editor (window, window with tabs, scrollable list, tab bar, checkbox, dropdown, buttons, search field, portrait, flag, progress bar, icon, modifier list, divider, header and text) are built from Victoria 3's own templates (gui/window_component_library.gui, gui/shared); buttons call scripted GUIs with the player country as root and grey out when is_valid fails; windows show while their variable is set and explain how to register them in gui/scripted_widgets.
- Victoria 3 GUI override order, measured in game: vanilla and mod files count together in load order (subfolders after the files of their folder) and the first definition of a type or template wins; a mod does not beat vanilla automatically, as it does in Crusader Kings III. "Take over type", the GUI editor, the mod compatibility check and the Compatch follow this (also measured: files of a folder load before its subfolders, and "_" sorts before letters), and the GUI editor refuses to edit a mod definition that loads after vanilla. replace_path hides the files of mods that load earlier, not of later ones.
- Key prefixes that a Victoria 3 folder does not support: the editor underlines them (red: the prefix has no effect there, orange: INJECT acts as REPLACE in script_values, scripted_effects, scripted_rules and scripted_triggers) with an explanation on hover, and the mod compatibility check lists them as findings for every mod.
- Fixed: the generator window listed the shipped Europa Universalis V packages in every game; it now lists only the packages of the current game (and packages without a game).
- New window layout: the menu bar keeps only Mod overview | Game | My <game> mods | Settings | Help, the big tools sit in a tile bar below it (order, visibility, size and label per tile are settings, tiles can be dragged), and one small toolbar collects the file buttons (New, Open, Save, Save all, Close, ⇄, acting on the focused workspace) with the old toolbar entries; its order, separators and visibility are free, it can be dragged into place or docked top, left, right or bottom, and labels can be hidden. Each workspace keeps Category, Filter, Icons, a new "Sort" menu (manual, name, category, origin) and, optionally, Notes, Bookmark and Bug buttons that act on that workspace. The previous layout stays available as "Classic" under Settings > Layout; old sessions start in the new layout with the four tools that became tiles hidden from the toolbar.
- Compatch merge, view A: keyboard shortcuts for the selected spot or block: O "Looks good", A take mod A, B take mod B, R "Reset", C open the compare window. With the focus in the preview on the right, Up and Down select the previous or next entry in the tree, so you can go through the list without the mouse. The keys are not active while typing in a text field or while "Edit" is open; the button tooltips name the key, and the hotkey list in the settings shows them all.
- Active mod: it is now chosen instead of guessed. Click "Mod: …" in the status bar (a list with search field) or open the "Mods" menu to pick a mod, or "Automatisch (offene Datei)" for the old behaviour (the mod of the file open in the editor). The choice is saved per game; the first start keeps the mod detected at that moment. If the chosen mod is removed or its folder is gone, PMT falls back to automatic and says so in the status bar. The active mod is the target of GUI take-overs and new GUI files and the default for patch recipes and the generator. "Mods verwalten" in the Mods menu opens the mod list as before (one click more).
- Generator packages (new window "Generator-Pakete" in the main menu): a package turns a form into many mod files at once, for example a whole national idea set. The form has head fields (e.g. a tag), groups and countable levels (e.g. categories, ideas, levels), multilingual texts with translation rules for all languages of the game, and images from an asset library. Templates use Scriban. Outputs are own files, localization per language, sections between markers inside existing files (markers of an older tool are recognised and kept), single lines in a block, synced blocks (only the sub-keys the form sets are replaced) and binary copies. A preview tab lists every file with its status and shows the change side by side; lines can be taken back with U. Generating writes everything as one undo step, either into the mod or into an output folder. Work states are saved per key, and each work state remembers its mod (picked in the form from the mods of the game or as a folder, not taken from the file open in the editor). The package format is described in docs/pmt-generator-packages.md.
- Generator packages: the IV2 national ideas package now ships with PMT. For the same input it writes the same keys, blocks and values as the Python IV2 generator (checked against it for an invented test set and for the BYZ set), except that the generic actions check the mod's current limit variable iv2_var_current_national_idea_limit instead of iv2_var_national_idea_limit and use the game's current automation category governmentreforms instead of governmentreform. It writes the 10 own files per tag, the static modifiers, the localization per language, the coat of arms and the sections in the 5 shared base files. Old entries of the tag without markers in the base files are removed before the new section is written, so sets added by hand or by older generator versions are not duplicated. An empty modifiers field leaves the existing static modifier block untouched; a filled one replaces its effects and keeps game_data. The coat of arms zip (coa_library.zip) is not shipped; choose it once with "Asset wählen" in the form. New in the package format: initial counts, blocking errors, package texts in all interface languages, language rules in templates, removal patterns for unmarked old entries, kept sub-keys for synced blocks, GUI type and template headers in block paths and skeletons for single lines.
- Generator packages: sets can now be read back from a mod. "Aus Mod einlesen" fills the form from the base mod (ideas, levels, modifiers, names and descriptions in every language, expensive levels, coat of arms); "Tags aus Mod übernehmen" reads the tags of another mod as work states, which "Erzeugen" then writes into your mod (this replaces merging two IV2 mods); "Mod prüfen" reads every tag of the base mod and lists, without writing, which files are missing, differ in content or only in formatting, how many old unmarked entries the base files hold and which static modifier blocks nothing uses any more, with "Öffnen" and "Ungenutzte entfernen" (trailing levels and ideas only) leading to the usual preview. The package format gets a "read" section (docs/pmt-generator-packages.md); the IV2 package has one.
- Generator packages: lookups. "Aus Datenbank" next to an idea name opens the idea database: advances, government reforms and laws/policies read live from the game folder (with their official texts in every language of the work state), and the nation ideas of the Python generator's idea database file, chosen once with "Asset wählen"; search, type and tag filters are remembered. "+ Modifier" next to a modifier field searches PMT's modifier index and inserts the modifier with a start value (yes, -0.1 for harmful ones, else 0.1); it can copy it to the higher levels of the idea with scaled values (value × level, e.g. 0.05 → 0.1 → 0.15 → 0.2), and the chips under each modifier field show the names and values as the game does, with ✕ to remove a modifier from one or all levels. "Wappen wählen" opens a picture grid of the coat of arms library with the tag's coat of arms preselected. Packages describe their own sources in a new "lookups" section (docs/pmt-generator-packages.md).
- Generator packages: package editor (main menu "Paket-Editor", or "Paket bearbeiten" / "Neues Paket" in the generator window). Packages are created, copied and deleted there and edited with masks instead of JSON: basics and targets, head fields, the chain of form levels with their fields, constants tables (with per-language cells), language rules, assets with their origin (game or mod/own), outputs with only the fields of their kind, templates in a Scriban editor with highlighting and a list of available names, and warnings and errors. "Prüfen" loads the package as a trial and checks every template (a click jumps to the line), "Im Generator testen" saves and opens the generator window on the package. Shipped packages like IV2 are read-only and can be edited as a copy. Packages can be exported as a .pmtgen file (work states and mod assets optional; assets from the game never) and imported again (only allowed entries, size limits counted while reading, id conflicts resolved). A new guide (F1, also in the generator window) explains packages with an example. Generator outputs whose rendered path would leave the mod or output folder are now refused. A copied or imported package keeps the original's marker id ("Markierungs-Kennung" on the basics mask), so it replaces the original's sections in a mod instead of writing them a second time.
- Generator packages: the package editor now edits reading back ("Einlesen") and lookups ("Nachschlagen") with masks too, so no package needs JSON editing any more. Patterns get a live check, "Vorschlag" builds a pattern from a file, block or localization key picked in a mod, and "Probelauf" reads one set from a mod and shows the matches per pattern and the result without writing anything. Each lookup source has a "Vorschau" with its first 50 entries or the reason why it finds none, and text fields get the option "Aus Datenbank nachschlagen". Renaming fields or sources updates their references. Reading and lookups now refuse paths that would leave the mod or game folder. Two new guide chapters (F1) explain both.
- Generator packages: "Prüfen" (and pmt-generator check) now renders every template once with sample values, so unknown names (e.g. a field the template uses but the package never defines) show up before generating instead of only in the preview. A .yml output that is not of kind "localization" is reported too.
- Generator packages: "Mit KI erstellen" (package editor and generator window) hands building a package to an AI of your choice. PMT assembles the task (a guide for any AI, the files of one finished set from your mod - ticked files are listed separately for quick unticking - or, to keep the task small enough for free chat AIs, only pasted code blocks with their mod path and "whole file"/"excerpt", your description, optionally the open package) as text to copy, as a file or as a folder, and takes the AI's answer back by pasting it or importing a folder, with the usual import checks and an automatic "Prüfen"; errors can be copied back for the AI. The guide also ships in the program folder (ai-guide/, usable as a Claude skill), and the new pmt-generator.exe lets an AI with file access check a package itself (check, probe, roundtrip). Reading sets back now also works for packages whose top level is a simple countable level.
- Generator packages, "Mit KI erstellen", code blocks: each block can carry a note that tells the AI what matters about it, blocks collapse to a one-line summary (click the header, or "Alle zuklappen"/"Alle aufklappen"), and "Aus Mod-Datei übernehmen" / "Aus Spieldatei übernehmen" open a file read-only with search, where the selected lines (or the whole file) become a new block with its path. Blocks from the game are marked as game files and serve the AI only as a model.
- Generator packages for sets in shared files: the new output kind "Abgleich nach Treffer" (syncMatching) replaces exactly the entries of a set inside a block or file - blocks, GUI templates and types, list values, unnamed if blocks and comment lines - in place and without markers, so re-generating an unchanged set changes nothing. Localization can write into shared files ("Schlüssel-Muster"), replacing only the set's keys instead of the whole file. A work state key can be made of several head fields (e.g. category and number: adm_18), and reading back finds keys in block names, fills head fields from the localization and collects values such as religions. All of it has masks in the package editor and a guide chapter "Gemeinsame Dateien".
- Generator packages: the new package "IV2 Ideengruppen" ships with PMT and writes one idea group of The Idea Variation 2 (category adm/dip/army/navy and number, e.g. adm_18) into all shared files at once: the group's actions, AI lists, statistics, country view, GUI types and tooltips, the selection window column, revolt and religion effects for religion groups, static modifiers, messages and the localization in every language. "Aus Mod einlesen" reads an existing group back, including its conditions, column, AI list, group type and religions. Checked against all 105 groups of a test copy of the mod: every group reads back and re-generates without errors; apart from whitespace and comments, the remaining differences are irregularities in the mod itself. Government and rank groups get the shared parts but not their own special files. New in the package format: flags with a regex pattern, values read as the content of a sub-block, and block path filters ("if[text]", "[!text]", "#2" for the second block of that name).
- Generator packages: "IV2 Ideengruppen" now also writes government and rank groups (AI list, selected trigger, remove and add effects and the modifier cases per government type or rank in the change and revolt effects) and mutually exclusive groups ("Schließt aus": the exclusion in the selection, the exclusive icon with its tooltip and texts). The religion field is now "Bedingungswerte" and holds religions, government types or ranks; saved work states stay valid. When a partner group does not exclude the group back, the preview warns and names the partner to read and generate again. New in the package format: the output kind "Prüfung" (check), which writes nothing and turns patterns missing from the planned text into preview warnings, and an own "output" per localization reading entry for texts in a second shared file.
- Package editor: on shipped packages "Probelauf", "Vorschlag" and "Vorschau" can be used again (only the inputs stay locked; "Vorschlag" shows the pattern to copy). A lookup folder with ".." is now reported as unsafe instead of as a missing game folder.
- Generator preview with target "output folder": a file that has no copy in the output folder yet is now compared with the mod's file it builds on ("Grundlage: Datei der Mod", status "neu · aus Mod-Datei"), so only the real changes are marked instead of the whole file looking newly generated. These files cannot be taken back line by line with U.
- Generator form: the image field (coat of arms) shows a preview of the chosen picture next to the list (DDS in DXT1/DXT5 and common image formats). The mod row is now called "Basis-Mod" with a short note that it provides the base files and is the target of "In Mod schreiben". The language rules have tooltips; a rule that another one already covers is greyed out ("English for missing translations" while English goes into empty or all languages anyway).
- Category names are translated: the seven built-in file categories (Text files, GUI files, Localization (YML), Defines (LUA), Important, Helper file, Other) and the folder categories of the game profiles (Graphics, Map, History, Music, Fonts, Decisions, Missions and the descriptions) were fixed German texts; they now follow the interface language in all eight languages. A built-in category you renamed keeps your name; typing the shown name in the Categories window keeps it translatable.
- Fixed: four more timing guards in tests (block window, searchable choice, GUI resolver, sibling matcher) failed when the release tool ran all test projects at once; they are now guards against gross regressions.
- Generator packages for sets spread over shared files: syncMatching can put a new set after an anchor ("insertAfter") instead of at the end, and can sort it into the right if = { limit = { ... } } block by condition ("ifLimit"), moving it when the condition changes. A numeric key field can count itself ("autoNumber"): a new set gets the next free number, skipping numbers whose localization key would collide in the game's hash. The new output kind jsonEntry writes one entry into a JSON file outside the mod (chosen once in the generator window, backed up before every change), and a package can show a hint after generating ("afterGenerate"). Building the hash index runs in the background with PMT's loading window and can be cancelled. All of it has masks in the package editor and guide chapters.
- Generator packages: the new package "IV2 dynamische Ideen" ships with PMT and creates, reads and edits the dynamic national ideas of The Idea Variation 2 (adm/dip/army/navy, e.g. army_53, with their levels) in all of the roughly 25 places an idea needs: static modifiers, actions, AI lists, setup effect, scripted GUIs and triggers, GUI shells, localization and messages in every language, the country view and the AI tag file. A new idea gets the next free number, a conditional idea goes into the matching if block of the setup effect, ideas are only deactivated, never deleted, and levels 2 to 4 use the innovation cost tooltip. Checked against all 485 ideas of the mod: every idea reads back, and re-generating changes nothing beyond a few documented irregularities of the mod.
- Generator packages, "Modifier ohne Idee": for packages with a candidates section (IV2 dynamic ideas) a new window lists the game's country modifiers that no idea of the mod uses yet, sorted into groups (estates, religion, government, goods …; the goods groups are hidden by default but stay visible greyed with their counts). Search, a regex to hide modifiers, "new only" for modifiers the latest script database import added, and "not as idea" marks. "Erzeugen…" creates a work state per chosen modifier with the next free numbers and the modifier's official name in every language; the values stay empty on purpose and generating refuses until they are filled in. F1 opens the guide chapter.

v0.9.1 (02.10.2026)
New
- Fixed: the release tool aborted at the "Tests" step because the real-save load test compared a 236 MB save against a 3 s limit while all test projects ran at once (6.5 s under load, 1 s alone). The limit is now a 15 s guard against gross regressions.
- Warnings after replacing (OR/NOR/AND blocks with one entry or none): saving a file (Save, Save all, Ctrl+S) now updates them automatically, as the refresh button does. Places that were fixed drop out of the list, the rest get their current line. It only runs when the saved file has warnings. With "show warnings in their own window", an open warning window is replaced when the list changed and closes when nothing is left; a window you closed stays closed.
- Result lists (Find & Replace window and results bar): you can now select several matches (Ctrl+click, Shift+click, Ctrl+A); Ctrl+C or "Treffer kopieren" copies all selected matches, one block each, separated by a blank line, and the new context menu entry "Alle Treffer kopieren" copies the whole list. A read-only text box under the list shows the code of the selected matches, so parts of a match can be selected and copied with Ctrl+C; it appears only while something is selected. Double-click still jumps to the match.
- Mod compatibility check, sense check: an entry whose copy only gives existing subkeys a new simple value (e.g. cost = 1 becomes cost = 2), with or without new subkeys, now gets the hint "Nur Werte geändert" (INJECT: is enough) instead of "Ersetzung nötig" (REPLACE:), because INJECT: overwrites an existing subkey in place (measured in Europa Universalis V). REPLACE: stays the advice for removed or reordered subkeys, changed sub-blocks and repeated keys. The same rule now also decides "Nur Ergänzung": a subkey inserted before existing ones (e.g. an else_if before else) or one that repeats an existing key is no longer called a pure addition, because INJECT: appends at the end and overwrites a repeated key.
- Compatch creator: the patch form "INJECT:" is now also offered when a subkey only gets a new simple value (e.g. cost = 1 becomes cost = 2), not just for pure additions. The patch then holds only the changed and the new subkeys, and INJECT: overwrites the existing subkey in place (measured in Europa Universalis V). Removed or reordered subkeys, changed sub-blocks and a new entry that repeats an existing key still get REPLACE: or a whole file. Fixed along the way: an addition that repeated a key the entry already had was offered as INJECT:, which would have overwritten that subkey instead of appending it.
- Desync analysis (OOS dump window), Europa Universalis V: new tab "MP-Prüfung" checks your own mods (or, with "ganzes Playset", the whole playset) for script that can make a multiplayer game go out of sync, for example has_local_dlc in synced script or console commands in .gui files that are not interface-only. Each finding shows its severity, file, line, context and an explanation; double click jumps to the file. With an OOS selected it checks the mods from the dump (unless "Vorabprüfung statt Dump-Mods" is ticked) and ranks their files as suspects by log leads, rule findings and terms from the state comparison. Log leads are matched against the mods in the dump (in the dump's load order), and a file with a log lead always ranks above files that only have rule findings. Findings can be marked harmless or confirmed as risky (context menu); the verdict is kept per game. The check only starts on "Prüfen" and nothing is written to mod files.
- Menu bar: "Komp-Patch Tool" now sits right next to "Mod-Kompatibilität prüfen".
- Fixed: the mod compatibility check reported .metadata/metadata.json (and other files directly in the mod folder, such as descriptor.mod or thumbnail.png) as a file conflict between two mods, and its sense check could call them redundant. These files describe the mod and are never loaded as game content, so they are now skipped, as the Compatch creator already did.
- Fixed: Compatch creator and mod compatibility check treated INJECT: as if it only appended subkeys, so a subkey that vanilla or another mod already sets appeared twice in the computed game state (e.g. gold = 10 and gold = 999) and such cases were marked uncertain. - The C-U tool is now the Compare und Update Tool with two tabs, each keeping its own comparison: Compare has the fields file A and file B (instead of the "Compare two files" dialog and the choose buttons) and the quick access buttons of Find in files (a click opens the file selection in that folder for the last used field, dragging a button onto field A or B inserts its folder; the buttons are shared with Find in files), Update lists the overridden files of the mod as a filterable list next to the editors; the editor buttons (differences, search, folding, save) sit directly above the editors, and the window remembers the last tab; the tooltip of the menu entry describes both tabs.
- Save explorer: metadata block, date field, compressed format and variables below an object come from the game profile; the debug mode hint no longer names only EU V.
- GUI editor: context folders and the override order of types and templates come from the game profile; for games where the first loaded file wins, "take into mod" names its files with the prefix 00_.
- File and folder dialogs remember their last folder per game instead of one folder for all games.
- Game selection lists the games by release date (EU IV, CK III, EU V) instead of alphabetically.
- Compatch merge window: one search field directly above the tree of every view searches the file path, the place and the key (the separate "Folder" field is gone); write patch, save work state and recheck all are large tiles (the small progress bar and cancel button next to them are gone, loading and cancelling happen in the loading window); the options of the work state are in a "Settings" menu with a link to the settings window, "Hide done" stays in the toolbar, and "Only uncertain" is now saved with the work state.
- Compatch start window: write mode, skip locked files, main mod as base and take over missing blocks start from the defaults in the settings instead of the last start; "Remember as default" now saves them there together with the file kinds.
- Compatch merge: a decision, a block decision or taking marked lines only merges the affected blocks again instead of all of them; with large mods (tens of thousands of places) this cuts the wait after each decision to about a quarter.
- Compatch merge: the action list only creates the entries you can see (the rest appear when a folder, file or block is opened) and sorts once per run; it is no longer rebuilt while the cards or document view is shown. With large mods this removes seconds of wait after each decision. On opening, only folders with conflicts are expanded, not every file.
- English UI: the remaining German texts in windows, dialogs, context menus, messages and status lines are translated, including startup messages, the Steam upload helper, game profile labels and the counting rules guide.
- Find & Replace: the search box has the keyboard focus right after Ctrl+F, so you can type immediately.
- Closing a document tab shows the document you had selected before, instead of an empty editor.
- The tooltip of "Register PMT as editor" explains that the game passes only the file and needs a restart when the path is entered in the game.
- Error log (EU V): the catalog now recognises unreadable mod metadata (named by the mod folder), errors while loading a save game, missing Wwise sound events and parsing errors whose closing line with file and line is missing from the log (Crusader Kings III too); the engine messages about the audio memory arena and the input context are hidden by default.
- Error log (Crusader Kings III 1.20): the vanilla message "Failed to find applicable culture set" of court scenes is recognised and hidden by default.
- Error log (Crusader Kings III): messages while loading a save game from an older version are recognised as save game messages (read errors without file, unknown dynasty templates, unknown faith keys) instead of parsing errors; missing head titles of rites and engine assertions have their own entries. The probe run with game version 1.20 showed the same messages as 1.19.
- Error log (EU V): read errors without a file name (in file: ""), which come from a loaded save game, are save game messages (info) instead of parsing errors without location.
- Crusader Kings III 1.20: script database and data type list checked against the logs of the new game version; all effects, triggers, event targets, modifiers and data types are read. Entries the game no longer lists (e.g. set_state_faith, the house_relation and house_aspiration lists) stay searchable and are marked as outdated.
Fixed
- Patch recipes, small fixes:
  - "Vorschau berechnen", "Anwenden" and "Bestehende Blöcke übernehmen" can no longer close PMT on an unexpected error; the message shows in the status line.
  - An unreadable memory file is reported in the preview and kept as "<id>.memory.json.broken" when applying, instead of being emptied silently.
  - Applying refuses a preview in which an adopted block was taken back with U while its removal from the source file was not, so the block cannot get lost.
  - "Block entfernen" removes every definition of a key defined twice in one run.
  - Derived list columns (several places, several baronies) follow file order instead of the order of the search forms.
  - Typos in section names ({?x}, {!x}, {*x}, {/x}) are reported like unknown placeholders.
  - A line starting with "# PMT-Unit" or "# PMT-Patch" in a template or block text skips the file with a warning instead of splitting the unit.
  - No trailing space when the target block's closing brace shares its line with other content.
  - A leading "/" in a target path no longer makes the same file appear twice.
  - Import dialogs take only checked rows that are visible under the current filter; a missing game folder has its own message instead of "Kein Mod gewählt".
  - Watcher:
    - Files with conflicts no longer show as covered, since applying skips them.
    - An existing but empty game folder is reported.
    - Vanilla folders hidden by the mod's replace_path are not scanned.
    - After applying, or after a vanilla update merge of the same mod, the watcher says the scan is out of date.
    - Renaming a rule no longer asks for a rescan.
    - Adding a file to a switched-off rule says that the rule is off.
    - Switching the recipe during a scan scans the new recipe afterwards.
- Compare und Update Tool: U no longer takes lines while the comparison is paused (one side cannot be read as script, e.g. a localization file); before, it could take lines at the positions of the previously shown file.
- Compatch merge, view A: U did nothing after marking lines in the column preview while the search box still had the keyboard focus (the U went into the search). Marking lines now moves the focus to the preview.
- "Merge nach Update": a mod file that no longer has the content PMT wrote (for example copied back by hand) loses its saved decisions when the run is opened again; before, its places showed as done although the result was no longer in the file. Works for files written from this version on.
- Compatch merge: taking marked lines that leave the result unchanged (for example only commented-out lines) now says so instead of "Taken".
- Compatch merge, "Merge nach Update" and the Compare und Update Tool read the operators ?= and != (Crusader Kings III, Europa Universalis V); before, "x ?= { ... }" was split into "x" and "? = { ... }", and a rewritten block came out as broken script.
- "Merge nach Update" wrote broken .gui files (Crusader Kings III, e.g. hud.gui): a changed top-level window or widget was moved into the types block. It now stays in place, new vanilla parts go where they are in vanilla, and rewritten blocks keep the tabs, depth and blank lines of the file; comment lines like "#####" no longer become "# ####".
- Compatch merge and "Merge nach Update": a block text made from marked lines keeps the formatting of the file it was taken from. Comment lines, blank lines, short blocks like size = { 144 70 } and the original line breaks stay as they are; before, the text was saved in the uniform layout of the compare columns. Block texts saved by an older version get the source formatting back when the merge is opened again.
- Undo of a file written by PMT restores the old file byte for byte, including its encoding (for example Windows-1252 in Europa Universalis IV) and BOM; before, special characters in such files could be lost on undo.
- Mod compatibility: .gui files are split into GUI types and templates like in the compatch merge (Europa Universalis V and Crusader Kings III); two mods changing the same type are found, and own top-level windows or widgets of two mods no longer count as a conflict on "window".
- Compatch merge: taking marked lines of a block with U (compare window, view A) decided every place of the block at once, and a later single decision in that block dropped the taken lines again; now each changed place gets its own decision (A, B, vanilla or own text) and the other places stay open. Only a change that matches no place still becomes a text for the whole block.
- "Merge nach Update" for files without old vanilla version: places where the new vanilla version and the mod are the same no longer show up in the action list (they appeared as places to check inside logic blocks, e.g. ai_weight_for_fascination of CK III innovations).
- Compatch merge, action list: right-clicking a single place (e.g. a GUI type with only one change) opened the menu of the file above it, so "take … for all" changed every place of the file; single places now have their own menu.
- Compatch merge and "Merge nach Update", Crusader Kings III: .gui files are split into their types and templates again; before, the whole types block (e.g. of gui/hud.gui) showed up as one huge file rest.
- Compare und Update Tool, Update tab: the installed game version is now detected for Europa Universalis V (from the game program, which has no launcher-settings.json) and Crusader Kings III (launcher folder next to the game folder); before, the version had to be typed in.
- Compare und Update Tool: the old vanilla version for "Merge nach Update" was chosen alphabetically ("1.10" before "1.9"); versions are now compared by number, and the version a file was last updated to counts first.
- Europa Universalis V: replace_paths entries name the folder without in_game/, main_menu/ or loading_screen/ (like "common/x"), as the game reads them; PMT compared them with the full path and missed hidden folders. Entries that start with in_game/ and similar have no effect in the game and are no longer counted.
- The mod folder from the game profile is shown with backslashes only (it showed mixed slashes like C:\Users\x/Documents/...).
- Crusader Kings III GUI editor: when the own mod and a dependency mod define the same type or template, the definition in the file first by path counts as effective, as measured in game; the playset order does not decide.
- With two PMT windows open (two games), closing a sub window such as Mods no longer brings the other game's PMT to the front; focus returns to the window it came from.
- Error log: Crusader Kings III log lines with a level field ([E], [D]) are read as separate messages instead of being joined into one.
- Crusader Kings III and EU IV: a mod whose .mod file next to the folder has a different name (e.g. "AGOT Flogis Buildings Mod.mod" next to "AGOT Flogis Buildings") now shows its name from descriptor.mod inside the folder; CK III mods no longer fall back to the folder name.

- Compare and merge (compatch, C-U tool): repeated blocks with an identifier (name, key or id), such as modifier_definition in estates_preload, are matched only by that identifier; two definitions with different keys are no longer merged into one because the rest looks alike, and new ones are listed under their identifier.
- Mod compatibility and compatch (EU IV): custom GUI entries (custom_button, custom_icon, custom_text_box, custom_window, custom_shield) are identified by their name, so two different buttons are no longer merged into one; estate crown land and the color lists (custom country, dynasty and region colors) count as whole files.

Country, unit, technology and bookmark files count as whole files.
